# Reading Lamp — 英語多読アプリ

Extensive Reading (ER, 多読) の研究知見にもとづいて設計した PWA です。スマホのホーム画面に追加してネイティブアプリのように使えます。

ホーム上部に「今日読むもの」と読書開始ボタンを配置し、起動後すぐに一篇を選んで読み始められます。読みかけの文章がある場合は、その再開カードを最優先で表示します。「最近の記録」はホームでは最新3件に絞り、保存済みの全履歴は分析・バックアップ・復元に引き続き利用します。

v2.9.2では画面内の日本語を見直し、週・月の記録、読後の案内、初回設定、リワードの説明を短い文に整理しました。リワード39件の題名も達成内容が分かる表現に修正しました。ID、条件、プライズ、英文データ、読書履歴との互換性は維持しています。

v2.9.3ではPWA更新時、更新版の英文データを保存できるまで旧版の英文キャッシュを残します。他のアプリのキャッシュには触れません。ホームの「今週のまとめ」は開いたときだけ表示し、ブラウザテストの旧文言を現行UIに合わせました。`npm test`に更新時のオフライン動作を再現するテストを追加しています。

v2.9.4ではバックアップに既読判定を加え、古い形式の復元は読了記録から判定を補完します。ダウンロード開始だけで保存完了とは扱わず、ファイルを確認してから記録します。対応端末ではファイル共有も選べます。未読文章が残り1〜2篇でも先に既読判定を消さず、WPM分析は復元された異常な計測値を除外します。英文2,000篇とリワード100種類の内容・IDは変更していません。

v2.10.0では多読の目的と読み方を、初回案内・ホーム・初回の本文画面・設定から開く使い方画面で段階的に説明します。日本語訳・単語帳・理解度テストを置かない理由を明示し、「難しすぎた」で途中終了した場合は辞書を使う代わりにレベルを下げる案内を表示します。

v2.10.1では、プライズの灯りカラーを選んだ際に、アプリ全体のアクセントと光が約1.6秒かけて穏やかに変化する演出を復活させました。端末のモーション低減設定が有効な場合は即時に切り替えます。

v2.10.2では、ホームの読み方カードを累計カウンターより上へ移し、読み方を先に確認できる配置にしました。WPMの表示には説明画面を追加し、速さを競う数値ではなく、無理のないレベルを選ぶ目安であることを明示しています。

v2.10.3では、Pixelなどが起動時に円形マスクを使う場合に備え、通常アイコンから内側の角丸四角を取り除き、maskableアイコンと同じ全面濃紺背景・安全領域へ統一しました。円の外周に角の残りが見える問題を防ぎます。

## 設計の土台となっている多読の原則

このアプリの仕様は、以下の原則から逆算して作られています。機能を足したり変えたりするときは、この表と照らして判断してください。

| 原則 | アプリでの実装 |
|---|---|
| テキストは「やさしい」こと（既知語95〜98%、未知語は100語あたり1〜2語） | レベル1〜10のグレーデッド・リーダー準拠の語彙帯。生成プロンプトの最優先ルールとして明記 |
| 「少し易しすぎる」レベルから始め、退屈になってから上げる | 読後に3択で読みごこちを申告。難のときは即座に1段階下げ、同じレベルで「易」が3回連続したときだけ1段階上げる |
| 量が学習効果の中核（年間100万語が目標） | ホーム画面の主役は累計語数カウンタ。1万→100万語の節目バーを表示 |
| 読書速度・流暢さの向上が主要な成果指標 | 本文が実際に表示されていた時間だけを計測し、直近5回の有効な語数÷読書時間から語/分 (wpm) を表示 |
| 辞書使用は最小限。分からない語は飛ばす | 本文画面に辞書機能を一切置かない。ホームで毎回リマインド |
| 読書そのものが報酬。読後テストは行わない | 振り返り・語彙リスト・理解度クイズの機能は持たない |
| 読み手が読みたいものを自分で選ぶ | テーマ選択（10テーマ＋自由入力＋おまかせ） |
| 退屈な本はやめてよい（脱落の自由） | 本文画面に「これはやめて、別の文章にする」。語数は加算せず、記録には残る |
| 毎日同じ時間に少量でも継続 | 連続日数と1日の目標語数（既定1,500語）を表示 |

## レベルの目安

| Lv | 語彙帯 | 目安 |
|---|---|---|
| 1 | 300語 | ごく易しい。短く単純な文 |
| 2 | 600語 | 日常的な話題 |
| 3 | 800語 | 単純な物語が読める |
| 4 | 1,000語 | 時制が自在に |
| 5 | 1,400語 | 描写や説明が増える（初期値） |
| 6 | 1,800語 | 抽象的な話題も少し |
| 7 | 2,500語 | 複文や比喩が自然に |
| 8 | 3,000語 | 論説的な文章も |
| 9 | 4,000語 | 原書に近い語彙 |
| 10 | 無制限 | 簡略化なし。一般書・報道と同水準 |

初期値はレベル5です。TOEIC 750 / B2 相当の力があっても、多読では実力より低いところから始めるのが正解です。「退屈なほど楽」と感じるまで上げないでください。上げるのを急ぐと、多読ではなく精読になってしまいます。

### WPM計測とレベル調整

- WPMは本文画面が表示され、ページが前面にある時間だけで計算します。別タブへの移動、画面ロック、アプリのバックグラウンド滞在は読書時間に含めません。
- 10秒未満の読了、または10未満・600超のWPMは誤操作や計測異常の可能性が高いため、WPM統計から除外します。ホームのWPMは、直近5回の有効記録について合計語数を合計読書時間で割って算出するため、短い文章だけが平均を大きく動かしません。語数と読了記録は通常どおり残ります。
- 「難しかった」は次の文章から1レベル下げます。「ちょうどよかった」は現在レベルを維持します。
- 「やさしすぎた」は同じレベルで3回連続した場合だけ1レベル上げます。途中でやめる、「ちょうどよかった」を選ぶ、または設定からレベルを手動変更すると連続回数はリセットされます。

## オフラインの文章バンク（APIキー不要）

初回からオフライン文章バンクが標準で有効です。Anthropic APIを一切呼ばずに、あらかじめ用意した文章から出題します。アプリ画面を先に起動し、文章データはバックグラウンドで端末へ保存します。ホームで保存状態を確認でき、失敗時の再試行とブラウザの保存保護を選べます。

- 現在収録：**2,000篇・345,407語**（ID `s001`〜`s2000`、レベル1〜10 × 全10テーマ）
- 全10テーマ × 10レベルの**100組すべてに最低18篇**を配置しています。
- 追加した3テーマ：`Mystery and adventure`（209篇）、`Travel and culture`（209篇）、`People and biography`（209篇）
- 既存テーマは履歴との互換性を保つため内部名を維持し、画面上では `Fantasy`・`Classics / Retellings`・`Society / World`・`Science / Technology` と分かりやすく表示します。
- 文章バンクは文体・語彙・構文を全件監査済みです。今回、既存1,710篇にも事実確認を広げ、根拠のない研究例、誤った題名、強すぎる因果表現などを含む31篇を追加修整しました。ID・レベル・テーマは維持しています。
- 今回の90篇は各レベル・各テーマへ9篇ずつ追加し、90個の異なるLevel×Themeセルに1篇ずつ配置しました。
- 全2,000篇を事実確認済みです。583篇は公的・専門機関等、192篇は古典原典と照合し、1,225篇は明示的な創作・仮想事例として外部事実の混入がないことを確認しました。詳細は`FACT_CHECK_REPORT.md`と`fact_check_all_2000.csv`にあります。
- `Famous books` は、十分古い古典作品の筋・人物・設定をもとに、多読用として新規に書き下ろしたリテリングです。原文や現代の翻訳文は転載していません。
- 全篇に教材管理用メタデータを付けています。アプリは `editorialStatus: "published"` の文章だけを出題し、下書き・確認中・公開終了の文章を文章バンクへ混ぜません。
- 選んだテーマとレベルの組み合わせの中で、一度読んだ文章は他のストックがなくなるまで再表示されません。未読が1〜2篇残っているときは候補数も1〜2篇になります。読み尽くすとその組み合わせの既読判定をリセットして次の周からまた出題します（直前に読んだ1篇だけは連続を避けます）
- レベル調整（読後の3択フィードバック）は文章バンクモードでも動作します

### 2,000篇の語彙レベル監査

全篇について、一般英語での語の使用頻度、極低頻度語、8文字以上の語、平均文長を監査しました。詳細は`VOCABULARY_AUDIT.md`、篇ごとの数値は`vocabulary_audit_2000.csv`に収録しています。さらに、数値上残る単一指標を全件編集判定し、`VOCABULARY_EDITORIAL_REVIEW.md`と`vocabulary_editorial_review_2000.csv`に判断理由を記録しました。新規90篇は全件が自動ガードレール内です。

- 運用ガードレール内：1,692篇
- 平均文長指標の超過：104篇（全件編集判定済み）
- 語彙指標の超過：305篇（平均文長との重複101篇、全件編集判定済み）
- 複数語彙指標の数値超過：2篇（確認済み、優先再編集0篇）
- 編集未判定：0篇

数値上の超過だけで不合格にはしていません。`children`や`together`のような長い日常語、動植物名、題材固有の科学語、上位レベルで必要な説明構造を全件確認し、中心概念を失う置換を避けて維持しました。未確認のまま残した篇はありません。

文章を追加する場合は、`stories.json`に本文情報と、`subtopic`・`contentType`・`editorialStatus`・`factChecked`・`reviewedAt`・`sourceWork`・`vocabularyVersion`を追加します。本文を変更した場合は`wordCount`も再計算してください。公開承認前は `editorialStatus` を `draft` または `reviewed` とし、出題可能にするときだけ `published` に変更します。詳しい定義は`METADATA_SCHEMA.md`にあります。

## 公開方法（おすすめ：GitHub Pages、無料）

1. GitHub に新しいリポジトリを作り、このフォルダの中身一式をアップロード
2. Settings → Pages で公開元を「main ブランチ / root」に設定
3. 発行された `https://アカウント名.github.io/リポジトリ名/` にスマホでアクセス
4. iPhone Safari なら共有 →「ホーム画面に追加」、Android Chrome なら右上メニュー →「アプリをインストール」

Netlify・Vercel・Cloudflare Pages へのドラッグ＆ドロップでも構いません。

GitHub Pagesだけで公開する場合、匿名集計と文章報告の受信APIは利用できないため、送信待ちデータは端末内に残ります。現在の配布版は問い合わせと文章報告用に `Reading.Lamp012@gmail.com` を設定しています。文章の問題は「メールで送る」を選び、メールアプリで利用者が送信した場合だけ届きます。「端末に保存」した報告はメールへ自動送信されません。自動収集を有効にする場合は、同一オリジンでAPIを提供できるVercel、Netlify Functions、Cloudflare Workersなどを使用してください。

### 公開前に設定する項目

`privacy.html`と`terms.html`は個人向け初回公開に合わせた内容で、メールの問い合わせ先を掲載済みです。公開前に配布ページへ**運営者名または屋号**を掲載し、`Reading.Lamp012@gmail.com`の受信を実際に確認してください。`config.json`の`supportEmail`はメールアプリで文章報告を作成するための宛先で、自動送信APIではありません。匿名集計と文章報告を自動収集する場合だけ、`DEPLOYMENT_CONFIG.md`に従って同一オリジンの受信APIを用意してください。詳細な確認順は`RELEASE_CHECKLIST.md`にあります。

## 使い方

1. 初回の案内で3つの英文から読みやすいものを選び、興味のあるジャンルと1日の目標を設定する
2. テーマを選び、タイトル・推定時間・語数が表示された3篇から読むものを選ぶ
3. 必要に応じて右上の歯車からレベルと1日の目標語数を調整
4. **辞書を引かずに**最後まで読む。分からない語は飛ばす
5. 「読み終えた」→ 読みごこちを3択で申告（これがレベル調整に使われます）
6. 語数・読む速さ・累計が記録される

## 個人向けリリース機能

- 初回オンボーディング：難度の異なる3つの短い英文から、辞書なしで止まらず読めるものを選んで開始レベルを決めます。手動調整、ジャンル、1日の目標も設定でき、設定画面から再表示できます。
- 今日の3篇：現在のレベルとテーマに合う未読文章を3篇提示し、タイトル、推定時間、語数、サブテーマから直接選べます。「選び直す」と「読みはじめる」も利用できます。
- オフライン準備：アプリ本体を先に起動し、2,000篇をバックグラウンド保存します。ホームで準備中・利用可能・失敗を確認し、再試行や保存保護を実行できます。
- 週間読書リズム：月曜〜日曜の読書日を7つの灯りで表示します。初期目標は週3日で、設定から週1〜7日に変更できます。連続日数を要求せず、休んだ日があっても今週の好きな日に戻れる案内を表示します。
- 短い一篇：オフライン文章バンクでは、現在のレベルと選択テーマを守ったまま、未読候補の短い35%から一篇を選べます。始める負担を下げたい日に使えます。
- リワード：累計語数、読了篇数、読書日、週のリズム、ジャンル・レベル探索、久しぶりの再開、短い一篇、途中で文章を替えた選択、お気に入りを含む100種類を集められます。未達や休みに減点はなく、一度獲得したリワードは失われません。総数を達成ノルマとして見せず、同じ指標の次の1段階だけを公開します。
- 灯りカラー：15種類の追加カラーをリワードとして解放し、標準色を含む16種類から選べます。獲得済みと現在挑戦できる段階のカラーだけを表示し、その先は関連リワードの達成後に公開します。累計語数だけでなく、読了篇数、読書日、週のリズム、レベル探索、短い一篇、お気に入りからもカラーを獲得できます。
- 画像・動画を使わない演出：ホームのリングは現在もっとも近い段階の進捗を示し、公開中のリワードに現在値と進捗バーを表示します。獲得時の点灯、カードの光、灯りカラー選択時の反応はCSSだけで表現し、端末の「動きを減らす」設定ではアニメーションを停止します。
- 次の目標：各系列で公開中の次段階から、今もっとも達成に近い1件だけをホームに表示します。利用者が以前から固定している目標は公開状態を維持し、おすすめと重ねず固定した1件だけを表示します。
- リワードの整理：画面タイトルを「リワード」とし、初期表示は公開中かつ達成に近い4件です。同じ種類だけに偏らないよう、可能な限り異なるカテゴリから1件ずつ選びます。必要なときだけ、現在公開中・獲得済み・カテゴリ別へ切り替えられます。未公開の将来条件は一覧へ並べません。
- 新しいプライズ：新しく獲得した灯りカラーには`NEW`を表示し、リワード画面で確認または装着すると確認済みになります。最近獲得したプライズは新しい順に3件だけ表示します。旧版ですでに獲得済みだったカラーへ突然`NEW`を付けない互換処理を行います。
- 候補の個別化：ジャンルがおまかせのときだけ、最近読了したジャンルを少し優先し、「興味を持てなかった」で途中終了したジャンルを一時的に減らします。選択したジャンルとレベルは常に優先し、設定から個別化をオフにできます。判定は端末内だけで行います。
- 久しぶりの再開：最後の読了から14日以上空いた場合、選択中のジャンルとレベルを変えずに、短めの3篇を優先して表示します。一篇読了すると通常の候補表示へ戻ります。
- 初回読了ガイド：最初の一篇を読み終えたときだけ、記録された内容と次回の始め方を読了画面内で案内します。確認後は繰り返し表示しません。
- バックアップ案内：10篇読了、または3篇以上を14日以上かけて読んだ後も未保存の場合に、ホームへ控えめに案内します。保存後は最終バックアップ日を表示し、30日経過したときだけ再案内します。
- 今週のまとめ：月曜から日曜までの読書日、読了篇数、語数、新規リワード数、読んだジャンル数、文章を替えた回数を端末内だけで集計します。
- 目標の固定：未獲得のリワードを一つ選び、ホームに固定できます。達成時は自動的に固定を解除し、次の候補へ進めます。
- 獲得後の導線：通知から「コレクション」「灯りを変更」「次の一篇」へ直接進めます。同じ系列に続きがある場合は、新しく公開された次段階も通知します。複数の通知がある場合は「次へ」も選べます。
- リワードの道：累計語数、読了篇数、読書日、読書リズム、探索、再開、読書スタイル、お気に入りの15系列を、達成済み・現在の段階・未公開の続きに整理して確認できます。単発条件は発見型として、獲得後にコレクションへ現れます。
- 比較と月間まとめ：今週と先週の読書日・語数を評価なしで比較し、月ごとの読書日・篇数・語数・リワード・ジャンル・WPMを確認できます。
- 継続支援の表示設定：固定目標または次の目標1件の表示、獲得通知をそれぞれオフにできます。通知をオフにしてもリワードは記録され、アクセシビリティ機能は制限されません。
- 匿名利用計測：初期状態はオフです。同意した場合だけ、開始・読了・途中終了などの日別件数とレベル・ジャンル別件数を最大90日分保持します。文章名、文章ID、正確な読書時刻、自由入力、APIキーは含みません。送信先未設定時は端末内だけに保存します。
- 匿名診断：文章名、文章ID、個別の読書日時、APIキーを含めず、集計値とリワード達成率だけをJSONで保存できます。この診断ファイルは自動送信しません。
- 読みかけの復元：読書中の文章、実際に読んだ時間、スクロール位置を端末へ自動保存します。再読み込み、PWA更新、ブラウザ終了の後もホームから続きへ戻れます。「読み終えた」の後に閉じた場合は、読みごこちの入力画面から再開します。
- お気に入り：文章バンクの各篇を保存・解除し、ホームのお気に入り一覧から再読できます。
- 文章の問題報告：問題の種類と任意の補足を選び、文章ID・レベルを含む報告を送信します。失敗時は最大100件を端末内へ保存し、オンライン復帰時に再送します。送信先未設定時の保存、共有、JSON書き出しにも対応します。
- 規約とプライバシー：ホームと設定から`terms.html`・`privacy.html`を確認できます。

新しいアプリ版が準備できると、画面下部に更新通知が表示されます。「更新する」を押すと新しいキャッシュへ切り替えて自動的に再読み込みします。「あとで」を選んだ場合は、次回起動時またはアプリへ戻ったときに再確認します。

ホームの「読書履歴の分析」を開くと、読了篇数、直近7日の語数、1篇平均語数、途中終了率、WPMの変化、テーマ別・レベル別の傾向を確認できます。途中終了の理由も集計されます。

読みかけの文章は開始時、読書中は15秒ごと、スクロール後、アプリがバックグラウンドへ移るときに保存されます。再開までの閉じていた時間はWPMへ加算しません。「今回は再開しない」を選んだ場合は読みかけデータを削除し、その文章を未読候補へ戻します。保存内容はこの端末内だけにあり、端末間では同期されません。

設定の「読書画面の表示」では、次の項目をプレビューしながら変更できます。設定はこの端末に保存され、次回起動時にも反映されます。

- 文字サイズ：16〜26px
- 行間：1.5〜2.2
- 書体：セリフ体／ゴシック体
- 本文背景：ナイト／セピア／高コントラスト

AI生成を使う場合は、設定で「オフライン文章バンク」をオフにし、Anthropic APIキーを入力します。一度保存すると同じ端末のブラウザに記憶され、ページの再読み込みやアプリの再起動後も自動で使われます。「AI生成する文章の目安語数」はこのモードでだけ表示・使用されます。オフライン文章バンクでは、各篇に保存された適切な長さをそのまま使います。また、自由テーマの指定はAI生成モード専用です。

しんどいと感じたら、途中で「これはやめて、別の文章にする」を押してください。理由を「難しすぎた」「興味を持てなかった」「長すぎた・時間不足」「用事などで中断」「その他」から選べます。「難しすぎた」のときだけ次から1レベル下げ、ほかの理由ではレベルを変えません。語数は加算されず、途中でやめたこと自体にペナルティはありません。

## 記録・お気に入り・リワードの書き出し

設定画面の「記録・お気に入り・リワードを書き出す (JSON)」でバックアップをダウンロードできます。履歴には日付・テーマ・文章ID・語数・wpm・有効読書秒数（`activeSeconds`）・計測有効性（`wpmValid`）・読書前後のレベル・読みごこち申告・途中終了理由が入り、お気に入り文章ID、獲得リワード、選択中の灯りカラーも一緒に保存されます。

保存を開始した日時は端末内に記録し、設定画面に最終バックアップ日を表示します。バックアップJSONのスキーマはバージョン4です。バックアップ日時そのものは読書履歴やリワードの判定には使用しません。

「記録・お気に入り・リワードを復元する (JSON)」では、書き出したファイルを読み込み、現在のデータを残したまま重複を除いて追加します。リワードと解放済みの灯りカラーも検証して統合し、以前の履歴だけのJSONにも対応します。日付、語数、WPM、レベル、文章IDなどを検証してから保存し、不正なファイルでは現在のデータを変更しません。端末内には新しい順で最大2,000件の履歴と、最大500篇のお気に入りを保持します。

端末内の履歴が途中で欠けた、配列でない、または一部に不正な記録が混ざった場合も、アプリ全体を停止させず、読み取れる記録だけで起動します。修復前の履歴は端末内に一時退避され、設定画面の「保存データを修復しました」からJSONとして保存できます。退避データにAPIキーや読みかけ本文は含まれません。内容を確認した後は同じ画面から削除できます。「記録をすべて消去する」を選んだ場合は退避データも削除します。

## アクセシビリティ

- 設定、初回案内、途中終了理由、問題報告画面に、読み上げ用のダイアログ名・説明・モーダル属性を設定
- 開いたときにダイアログ内へフォーカスを移し、Tabキーをダイアログ内で循環
- Escapeキー、背景クリック、閉じるボタンで終了し、元の操作位置へフォーカスを戻す
- 背景を操作対象外にし、モーダル表示中の本文計測を一時停止
- スライダーの現在値を読み上げ用テキストとして提供
- 復元結果とエラーをライブ領域で通知
- 高コントラスト本文テーマと、読み手に合わせた文字サイズ・行間・書体を提供

## PWAアイコン

Androidの円形・角丸・スクワークルなどのマスクで使われる専用maskableアイコンを192pxと512pxで収録しています。起動時に端末が通常アイコンを選んだ場合も輪郭が崩れないよう、通常版とmaskable版は同じ全面濃紺背景を使います。ランプと本は中央の安全領域へ収め、外周に透過や内側の角丸四角を置いていません。`manifest.json`では通常用を`purpose: any`、専用版を`purpose: maskable`として分けています。

`manifest.json`には既存の`start_url`と同じ明示的なアプリID、言語、教育・書籍カテゴリを設定しています。iPhone向けのホーム画面表示メタデータも`index.html`に含めています。

## 注意点

- 標準のオフライン文章バンクではAPIキーを使用しません。
- AI生成モードのキーは、この端末の`localStorage`に保存します。設定画面の「この端末からAPIキーを消去」でいつでも削除できます。共有端末や第三者が操作できる端末には保存しないでください。
- `localStorage`は暗号化された秘密保管庫ではありません。同じ配信元で動くJavaScriptや、端末・ブラウザの利用者から読み取られる可能性があります。信頼できる場所に配置したアプリと個人所有の端末でのみ使用してください。
- AI生成時はブラウザからAnthropic APIへ直接キーを送ります。通信先はCSPでAnthropicと同一オリジンのみに制限し、外部フォントなどの第三者通信も削除しています。
- 多人数へ公開する場合は、利用者にAPIキーを入力させず、認証・利用上限を備えたサーバー側プロキシへ移行するのが最も安全です。本版はGitHub Pagesなどの静的公開を維持するため、端末内保存方式を採用しています。
- API 利用には従量課金が発生します（1セッション数円程度が目安）。
- 生成される文章は毎回AIが新規に書き下ろすオリジナルです（実在の書籍・記事からの引用ではありません）。
